# Enterprise v3.4.1

## Reliability
- Fixes the idle-time Electron `TypeError: Object has been destroyed` crash caused by a hidden X BrowserWindow `closed` handler dereferencing `win.webContents` after destruction.
- Captures the remote `webContents.id` before window teardown and cleans media policy state using the stored ID.
- Keeps background collection failures inside the application's guarded error/status path.

## X login routing
- Verifies the selected direct/Tor route before opening the X login flow.
- If Tor is enabled, login waits for a verified Tor route instead of opening against the fail-closed proxy.
- Adds login-window navigation/render diagnostics.
- Allows Google/Apple OAuth provider popups inside the same isolated X session partition.

## Identity avatars everywhere
- Collects author display name and profile-image URL from visible X posts/replies/comments when available.
- Caches avatar images locally under the application user-data directory.
- Uses the isolated X session (and its Tor route when enabled) for avatar retrieval.
- Shows cached avatars across Target Sources, Live Feed, Search, Analyst Notes, follower/following lists, common identities, overlap tables, relationship mind map, entity mentions/source chips, collection-health rows, network deltas, change events, run logs, and archive status.
- Falls back to an initial when no profile image is available.

## Neon relationship map
- Uses strong neon red, green, pink, orange, yellow, blue/cyan, purple, and aqua accents.
- Monitored target clusters receive distinct neon colors.
- Solid relationship lines represent identity-follows-target; dashed lines represent target-follows-identity.
- Target and common-identity nodes can display cached X profile pictures.

## Windows icon
- Keeps the compiled EXE/NSIS icon configuration and also copies `build/icon.ico` to `resources/app-icon.ico`.
- BrowserWindow instances load the unpacked runtime icon from a normal filesystem path in packaged builds.


## v3.4.1 avatar correction
- Target profile avatars are now selected only from the monitored profile's `/username/photo` header anchor, never from the first document-wide `profile_images` element.
- A one-time migration invalidates the v3.4.0 avatar cache and removes known contaminated target-avatar references.
- Previously collected correct tweet/network avatar URLs are reused immediately where possible.
- Monitored targets are re-verified in the background and their avatar cache entries are force-refreshed.

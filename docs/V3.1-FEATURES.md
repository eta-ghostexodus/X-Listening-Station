# Enterprise v3.1.4 additions

## Campaign workspaces
Campaigns are now the top-level workspace. Create as many as practical for separate purposes such as threat intelligence, news monitoring, safeguarding, brand monitoring, or research. Each campaign has a user-defined name, purpose, and description and isolates its monitored sources, findings, networks, notes, presets, entities, telemetry, archive progress, and reporting context.

The left navigation provides immediate campaign switching plus **New**, **Edit**, and **Manage** controls. Campaigns can also be duplicated to reuse source/preset/settings configuration without copying previously collected evidence.

## Highlight presets inside Search
Search now contains its own preset manager. Presets support:

- Any number of saved presets.
- Keywords and multi-word phrases.
- `ANY` or `ALL` matching.
- Case-sensitive or case-insensitive matching.
- Optional source scoping.
- Create, edit, delete, enable/disable, and re-run.
- A **Preset Matches Only** search filter.
- Automatic highlighting of matched phrases in search results.
- Match badges identifying which preset produced the hit.

Existing archive records are re-evaluated when a preset is saved or re-run, while newly collected records are checked during ingestion.

## Persistent Tor routing control
The bottom-left navigation includes a persistent Tor control:

- **CONNECT OVER TOR** when disabled.
- **DISCONNECT OVER TOR** when enabled.
- Green status indicator only after the connection is verified as Tor.
- Red status indicator when Tor is disconnected/unavailable.
- Displays the detected local SOCKS port and Tor exit IP when verification succeeds.

The application probes local SOCKS ports `9050` and `9150`, so Tor Browser or a Tor service must already be running. When Tor is requested but cannot be verified, X Listening Station fails closed rather than silently reverting X traffic to the direct network. Both the authenticated X partition and Electron's default renderer session receive the same proxy route while Tor is enabled.

Important: routing X Listening Station through Tor does not make a logged-in X account anonymous to X. Account identity, application behavior, browser characteristics, and other signals may still identify the session.

## One-click image evidence collection
The main command bar contains an always-visible **IMAGES: ON/OFF** button for the active campaign. Each monitored source also has its own easy **IMAGES ON/OFF** override.

When image retrieval is enabled:

- Visible X post images are downloaded through the authenticated Electron network session.
- Files are stored under the application's local evidence-media directory, separated by campaign and finding.
- Each stored image records source URL, content type, size, collection time, and SHA-256 hash.
- The Live Feed/Search renderer loads the locally archived copy rather than linking directly to the external media URL.

When disabled, textual/metadata collection continues but the image file is not downloaded. Previously archived images are not automatically deleted merely because retrieval is switched off.
